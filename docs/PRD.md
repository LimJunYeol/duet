## 2. 제품 정의
유저가 캐릭터를 선택해 1:1로 대화한다. 캐릭터는 고정된 페르소나와 말투를 유지하고,
이전 대화를 기억(요약 메모리)하며, 응답은 토큰 단위로 스트리밍된다.
글로벌 서비스를 가정해 응답 언어는 세션의 locale을 따른다.

- 코드네임: Duet (유저와 캐릭터의 이중주)
- 형태: REST/SSE API + 기능 확인용 웹 UI
- 유저: 캐릭터 대화형 엔터테인먼트 이용자 (성인)

## 3. 유저 스토리
| ID | 스토리 | 마일스톤 |

| US-4 | 응답 도중 네트워크가 끊겨도 다시 접속하면 끊긴 지점부터 이어서 받는다 | M2 |
| US-5 | 응답 생성을 중단할 수 있다 | M2 |

## 4. 기능 요구사항
### 4.1 MVP (M1)
- 캐릭터: 목록/상세 조회. 시드 3명(성격·말투·금기가 서로 다름).
- 세션: 생성(캐릭터·locale), 내 세션 목록, 상세. 생성 시점의 프롬프트 버전에 고정.
- 메시지: 전송 → SSE 스트리밍 응답, 히스토리 커서 페이지네이션.
- 컨텍스트: 시스템 프롬프트 + 최근 대화를 토큰 예산 내에서 조립.
- LLM 연동: OpenAI 호환 스트리밍, 타임아웃 3종, 첫 토큰 전 재시도·폴백 모델.
- 인증: 개발용 로그인(handle → JWT).

### 4.2 안정성 (M2)
- 부분 응답 저장·이어보기(Last-Event-ID), 중단, 멱등성 키, 세션당 동시 생성 1개.
- 레이트리밋(분당 토큰 버킷) + 플랜별 일일 한도.
- Kafka 이벤트 발행, worker의 사용량 집계.

### 4.3 AI Harness (M3)
- 입력 모더레이션(동기), 출력 모더레이션(스트리밍 룰 + 비동기 판정), 리뷰 큐(선택).
- 요약 메모리 worker.
- 프롬프트 버전 관리, 평가 CLI, CI 게이트.

### 4.4 성능·배포 (M4~M5)
- mock-llm, 부하 테스트, 100만 행 시드, 병목 개선 기록, AWS 배포.

## 5. 비기능 목표
측정 조건: apps/mock-llm, TTFT 300ms · 40 tok/s · 응답 120 토큰 고정, 오류율 0%.

| 지표 | 목표 | 도전 |
|---|---|---|
| 동시 스트리밍 세션 | 500 | 1,000 |
| 백엔드 부가 지연 (관측 TTFT − mock TTFT) p95 | < 100ms | < 50ms |
| 생성 오류율 | < 0.5% | < 0.1% |
| 히스토리 조회 p95 (messages 100만 행, limit 50) | < 30ms | < 15ms |
| 이벤트 처리 지연 (발행 → 집계 반영) p95 | < 2s | < 1s |
| 정상 완료율 (complete / 전체 생성) | ≥ 99.9% | — |

수치는 `load/results/`에 측정 조건·커밋 해시와 함께 기록한다. 조건 없는 수치는 무효.

## 7. 안전 정책 (변경 불가)
- 모든 캐릭터는 성인이며 성적 콘텐츠를 생성하지 않는다. 미성년자 관련 요청은 어떤 맥락이든 차단한다.
- 자해·자살 신호가 감지되면 캐릭터 톤을 유지하되 전문적 도움을 권하는 고정 응답으로 전환한다.
- 개인정보(전화번호·주소 등) 요구·노출을 차단한다.
- 판정 실패 시 정책: 입력 모더레이션은 fail-open(로그·메트릭 필수), 출력 하드블록 패턴은 fail-closed.
- 위반 판정 메시지는 읽기 시 `[removed]`로 대체하고 원문은 리뷰 큐에서만 노출한다.

## 9. 용어
- **TTFT**: 요청 전송부터 첫 `delta` 이벤트 수신까지의 시간
- **세션**: 유저–캐릭터 1개 대화 스레드
- **생성(generation)**: assistant 메시지 1개를 만드는 작업 단위. 상태 머신을 가짐
- **프롬프트 버전**: 캐릭터 시스템 프롬프트의 불변 스냅샷. 세션은 하나에 고정됨
- **요약 메모리**: 오래된 원문을 대체하는 세션 단위 요약 텍스트
