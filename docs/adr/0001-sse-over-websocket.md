# ADR-0001 스트리밍 전송은 SSE

- 날짜: 2026-09-09 · 상태: 채택
- 티켓: BE-18

## 맥락
LLM 응답을 토큰 단위로 클라이언트에 밀어주어야 한다. 방향은 서버→클라이언트 단방향이고,
재접속 시 끊긴 지점부터 이어받는 기능(US-4)이 필요하다.

## 결정
HTTP/1.1 기반 Server-Sent Events. POST 요청의 응답 본문을 SSE로 스트리밍하고, 이어보기는 GET + `Last-Event-ID`.

## 대안과 기각 이유
- WebSocket — 양방향이 필요 없고, 프록시·로드밸런서 설정과 재접속 로직을 직접 구현해야 함. 타이핑 표시·읽음 같은 양방향 기능이 생기면 재검토.
- Long polling — 델타 단위 지연이 커지고 서버 부하가 큼.

## 결과
- 얻는 것: 표준 재접속(`Last-Event-ID`), 단순한 서버 구현, HTTP 미들웨어(인증·레이트리밋) 재사용.
- 잃는 것: POST 응답 SSE는 브라우저 `EventSource`로 못 읽어 클라이언트 파서가 필요. 단일 연결 수 제한(HTTP/1.1 브라우저당 6개)은 HTTP/2 배포로 해소.
- 재검토 조건: 클라이언트→서버 실시간 신호(타이핑, 프레즌스)가 요구될 때.
